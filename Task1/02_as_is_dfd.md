# Диаграммы потоков данных (AS-IS)

## 1. Общая характеристика

В текущей архитектуре данные:
- передаются вручную
- хранятся в файлах
- не имеют единого источника истины (single source of truth)
- не отслеживаются (нет data lineage)

---

## 2. Основные процессы

### 2.1 Запись пациента

Поток:
Пациент → Ресепшен → Excel → File Server

Особенности:
- ручной ввод
- хранение в Excel
- отсутствие валидации
- нет контроля доступа

---

### 2.2 Приём пациента

Поток:
Врач → Excel / PDF → File Server

Особенности:
- медицинские данные в файлах
- доступ не ограничен
- нет аудита

---

### 2.3 Лаборатория

Поток:
Врач → Email → Лаборатория → Excel → Врач

Особенности:
- передача данных через email
- нет API
- нет фильтрации данных

---

### 2.4 Оплата

Поток:
Пациент → Кассир → 1С + Excel → ККМ

Особенности:
- двойной ввод
- рассинхронизация данных

---

## 3. Основные проблемы потоков

- нет шифрования
- нет контроля доступа
- нет аудита
- нет централизованного хранения
- нет контроля интеграций

---

## 4. Вывод

Текущая архитектура:
❌ не масштабируется  
❌ небезопасна  
❌ не соответствует требованиям работы с ПДн

Требуется переход к сервисной архитектуре с контролем потоков данных
