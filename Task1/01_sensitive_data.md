# Классификация и выявление конфиденциальных данных

## 1. Общий подход

В компании «Медикаменте» отсутствует формализованная модель классификации данных.  
Данные хранятся в Excel, файловых хранилищах и почте без разделения по уровням чувствительности.

Для дальнейшей трансформации вводится классификация данных по принципам:
- Privacy by Design
- Data Minimization
- Least Privilege
- Data Classification & Tagging

---

## 2. Категории данных

### 🔴 MEDICAL (медицинская тайна — критичные данные)
- диагнозы
- медицинская история
- результаты анализов
- назначения врача
- заключения

📌 Требования:
- максимальный уровень защиты
- доступ строго по роли + цели (ABAC)
- обязательный аудит доступа

---

### 🟠 PII (персональные данные)
- ФИО
- дата рождения
- телефон
- email
- адрес проживания
- паспортные данные (если есть)

📌 Требования:
- шифрование
- masking при отображении
- ограничение доступа

---

### 🟡 FINANCE (финансовые данные)
- платежи
- чеки ККМ
- договоры
- история оплат

📌 Требования:
- шифрование
- изоляция от медицинских данных

---

### 🟢 INTERNAL (служебные данные)
- расписания врачей
- загрузка кабинетов
- операционные данные

---

## 3. Неучтенные источники данных (критический риск)

Выявлены источники, которые не контролируются:

- Excel-файлы на общем диске
- PDF/JPG сканы
- вложения в email (Exchange)
- локальные выгрузки из 1С
- копии данных на рабочих ПК

📌 Проблема:
данные существуют вне системы контроля → высокий риск утечки

---

## 4. Вывод

Текущая модель:
- не учитывает чувствительность данных
- не обеспечивает контроль доступа
- не соответствует требованиям законодательства РФ

Необходимо:
- внедрение data classification
- централизованное хранение
- tagging + policy enforcement
