
# Обоснование выбора стратегии

Выбрана стратегия: **Parallel Run**

## Почему не другие

### High-level design
+ хорош для greenfield
- не решает проблему миграции данных и перехода пользователей

### Branch by abstraction
+ подходит для кода
- плохо применим к данным и интеграциям

## Почему Parallel Run

Плюсы:
- минимизация риска простоя
- возможность постепенного переключения
- тестирование на реальной нагрузке
- rollback возможен

Минусы:
- сложность синхронизации данных
- удвоенная нагрузка на инфраструктуру

## Вывод

Для системы с медицинскими и финансовыми данными это **самый безопасный вариант**
