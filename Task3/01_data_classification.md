
# Классификация данных и защита

## Основная таблица

| Данные | В чем необходимость защиты | Инструменты защиты |
|--------|--------------------------|-------------------|
| MEDICAL (диагнозы, анализы) | Медицинская тайна, высокий риск утечки, требования законодательства | AES-256, TLS, ABAC, Audit, Masking |
| PII (ФИО, телефон) | Персональные данные, требования 152-ФЗ | AES-256, TLS, RBAC/ABAC, Masking |
| FINANCE (платежи) | Финансовые риски, мошенничество | AES-256, TLS, Tokenization |
| INTERNAL (расписание) | Внутренние данные компании | RBAC, Audit |
| PUBLIC | Нет критичных рисков | Базовая защита |

## Состояния данных

- At Rest → базы данных, файлы
- In Transit → API, интеграции
- In Use → обработка в сервисах

## Вывод

Критичные данные требуют защиты во всех состояниях.
